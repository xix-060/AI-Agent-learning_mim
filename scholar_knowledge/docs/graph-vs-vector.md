# 为什么学术场景要"知识图谱 + RAG"？

## 纯向量 RAG 局限
- 擅长语义相似：问"LLM 综述" → 命中相关论文摘要
- 不擅长关系推理：问"哪篇论文被引用最多""XX 和 YY 是否合作过"
  → 需要引用/共著关系遍历
- 不擅长聚合：问"RAG 领域近 3 年哪些论文最热门"

## 学术图谱的价值
| 能力 | 向量 RAG | 知识图谱 |
|---|---|---|
| 语义相似检索 | ✅ 强 | ❌ |
| 引用/共著关系 | ❌ | ✅ 强 |
| 多跳推理 | ❌ | ✅ |
| 聚合统计（被引数） | ❌ | ✅ |
| 可视化展示 | 无 | ✅ 漂亮（面试加分）|

## GraphRAG = 图谱 + 向量 混合
1. 向量检索：召回语义相近论文/关键词
2. 图谱检索：从召回实体沿边扩展 1-2 跳取邻居（作者/引用/合作）
3. 合并去重：图谱路径(结构化证据) + 文本片段(语义证据)
4. LLM 综合生成回答

## 本项目图谱设计
节点类型：论文、作者、关键词、会议/期刊
关系：
- 论文 -[作者]-> 作者
- 论文 -[关键词]-> 关键词
- 论文 -[引用]-> 论文
- 作者 -[共著]-> 作者
- 论文 -[发表于]-> 会议/期刊
