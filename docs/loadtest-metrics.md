# 压测核心指标（面试必背）

## QPS / RPS（吞吐）

每秒完成的请求数。注意区分：

- 请求 QPS：POST /chat 算 1
- token 吞吐：每秒生成 token 数（LLM 场景更本质）

## 延迟分位数（Latency Percentiles）

| 指标  | 含义         | 关注点            |
| --- | ---------- | -------------- |
| P50 | 一半请求快于此值   | 典型体验           |
| P95 | 95% 请求快于此值 | 大多数用户体验        |
| P99 | 99% 快于此值   | 长尾（触发告警/投诉的来源） |

只看平均值会被长尾骗：平均 1s 可能 P99 = 8s

## TTFT（Time To First Token）

LLM 特有指标：首 token 延迟。
流式场景用户体感 ≈ TTFT，而非总时长。Prefill 越长 TTFT 越大。

## 压测方法论

1. 阶梯加压：并发 1→5→10→20→40，找拐点
2. 每档稳定跑 60s+
3. 拐点 = QPS 不再涨而延迟陡升 → 系统容量上限
