# LoRA 论文精读

> 论文：LoRA: Low-Rank Adaptation of Large Language Models
> 作者：Edward J. Hu, Yelong Shen, Phillip Wallis, et al.（微软）
> 时间：2021（arXiv:2106.09685），ICLR 2022

***

## 1. 解决什么问题？

**痛点：全参数微调太贵。**

大模型（如 GPT-3 175B）做下游任务适配，传统方式是全参数微调——更新全部权重。问题在于：

- **优化器状态吃显存**：Adam 要为每个参数存 2 份状态（动量、方差，fp32），175B 模型的优化器状态就要上 TB 级显存（远超单卡容量）。
- **每个任务一份完整权重**：175B 模型存一份就 \~700GB，n 个任务要 n 份，存储/切换都贵。

**LoRA 的答案**：冻结原始权重，只训练注入的少量"低秩"参数，**效果接近全参数微调**，且可训练参数降低 10,000×、显存降低 3×。

***

## 2. 核心思想：低秩分解

**关键观察（论文动机）**：Aghajanyan 等 (2020) 发现，预训练模型在下游适配时存在 **"本征维度 (intrinsic dimension)"** —— 即使把优化限制在一个很低维的子空间里，模型仍能有效学习。也就是说，**微调时的权重变化 ΔW 是"低秩"的**。

**低秩分解**：不直接学完整的 ΔW，而用两个小矩阵的乘积近似：

```
ΔW = B × A
```

其中（论文原文以一层权重 W0 ∈ R^(d×k) 为例；为简化讨论先用方阵 d×d）：

- **W0**：原始权重 (d×d)，**冻结不动**
- **A**：降维矩阵 (r×d)，r << d（如 r=8）
- **B**：升维矩阵 (d×r)
- **ΔW = BA**：(d×r)×(r×d) = (d×d)，形状与 W0 一致

**初始化**（论文 3.1 关键细节）：

- A 用高斯随机初始化
- B 初始化为 **0**
- 所以训练开始时 ΔW = BA = 0，模型行为 = 原始预训练模型（不会一上来就崩）

> 一般情形：W0 ∈ R^(d\_out×d\_in)，B ∈ R^(d\_out×r)，A ∈ R^(r×d\_in)，r << min(d\_in, d\_out)。秩 r 控制了"能学多复杂的变化"。

***

## 3. 为什么省显存？

只训练 A、B，原始 W0 冻结（不需要为它存优化器状态）。

| <br /> | 参数量 | 说明               |
| ------ | --- | ---------------- |
| 原始全量微调 | d²  | 更新整个 W0，且要存优化器状态 |
| LoRA   | 2rd | 只训练 A（rd）+ B（dr） |

**算一笔账**（r=8, d=4096，典型 7B 模型隐藏维度）：

- 原始 W0：4096 × 4096 = **16,777,216** 个参数
- LoRA（A + B）：8×4096 + 4096×8 = 32,768 + 32,768 = **65,536** 个参数
- 占比：65,536 / 16,777,216 ≈ **0.39%**，减少 **99.6%**

> 论文实测：在 GPT-3 175B 上，可训练参数降低约 **10,000×**，GPU 显存需求降低约 **3×**。

**为什么是 3× 而不是 1000×**：虽然可训练参数降了上万倍，但前向/反向仍要算完整激活、读完整 W0，这部分显存省不了。3× 主要来自"省掉优化器状态 + 梯度"。但可训练参数的骤降让**存储/切换任务**极其便宜（一个任务只需几 MB 的 LoRA 模块）。

***

## 4. 训练时怎么走？

**前向传播**：

```
h = W0 x + ΔW x = W0 x + BA x = (W0 + BA) x
```

即冻结的原始权重 + 低秩更新，一起作用到输入。

**反向传播**：

- 梯度只对 A、B 计算（W0 冻结，无梯度、无优化器状态）
- 只更新 A、B 这 2rd 个参数

**推理时**：

- 可训练完后把 **BA 直接合并进 W0**：W = W0 + BA
- 合并后推理路径与原模型完全一致，**无额外延迟**（这是 LoRA 相对 Adapter/Prefix-tuning 的一大优势——后两者要在推理时插入额外层/token）

**任务切换**：

- 保留一份冻结的 W0，每个任务只存一个很小的 BA 模块
- 换任务 = 换 BA，几乎零成本

## 5. 关键超参数

| 参数              | 含义     | 常用值                           |
| --------------- | ------ | ----------------------------- |
| r (rank)        | 低秩维度   | 8 / 16 / 32                   |
| alpha (α)       | 缩放因子   | 常取 r 的 2 倍                    |
| target\_modules | 应用到哪些层 | q\_proj, v\_proj / all-linear |

**α 的作用（论文 3.1 原生）**：实际更新用 **ΔW = (α/r) · BA**。引入 α 后，调 r 时不必重新调学习率（α/r 把不同秩的更新幅度归一化）。常用经验 α = 2r。

> 说明：
>
> - **α/r 缩放、A 高斯/B 零初始化** 是论文原生的。
> - **target\_modules / all-linear** 是 PEFT 库（如 HuggingFace `peft`）的工程约定，非论文术语。论文本身主要把 LoRA 加在 attention 的 q\_proj、v\_proj 上。
> - 论文实验结论：**q,v 加 LoRA、r=8 已可媲美全参数微调**；加到更多层或用更大 r 并不一定更好（这反过来说明 ΔW 确实低秩）。

***

## 6. QLoRA = 量化 + LoRA

（QLoRA 是 Dettmers 等 2023 的后续工作，非 LoRA 论文本身，常一起讲）

- 把原始 W0 **量化到 4bit**（省 \~75% 权重显存）
- 在 4bit 冻结模型上做 LoRA 微调（A、B 仍为高精度可训练）
- 反向传播用 paged optimizer 防溢出
- 效果接近全参数微调
- 7B 模型只需约 **6–8GB 显存**即可微调（消费级 GPU 能跑）

***

## 7. 手算示例

设 d=512, r=8（单层方阵）：

| 项             | 计算        | 参数量     |
| ------------- | --------- | ------- |
| 原始 W0         | 512×512   | 262,144 |
| LoRA A        | 8×512     | 4,096   |
| LoRA B        | 512×8     | 4,096   |
| LoRA 总计 (A+B) | 4096+4096 | 8,192   |

- 参数占比：8,192 / 262,144 ≈ **3.1%**，减少 **96.9%**
- 显存（float32，仅权重）：
  - 原 W0：262,144 × 4B = 1,048,576B = **1 MB**
  - LoRA：8,192 × 4B = 32,768B ≈ **0.03 MB**

## 8. 实验结论（论文第 5 节，看表格）

论文在 GPT-3（125M \~ 175B）及 RoBERTa/DeBERTa 上做了系统对比，关键结论：

1. **效果媲美甚至超越全参数微调**：在 GPT-3 175B 上，LoRA（q,v、r=8）在多项基准（RACE、WSC、ANLI、BoolQ、CB、COPA、MultiRC、RTE、WiC、WIC 等）上平均分 **略高于** 全参数微调。
2. **可训练参数降 \~10,000×、显存降 3×**，且**无推理延迟**。
3. **秩很小就够**：r=1/2/4/8 已能很好适配；**r=8 常常最优**，再增大 r 收益不明显甚至略降 —— 印证"ΔW 低秩"假设。
4. **优于其他高效方法**：相比 Adapter 层、Prefix-tuning、BitFit，LoRA 在相当或更少参数下效果更好，且推理无额外开销。
5. **加在 q,v 通常足够**：相比加在全部 (q,k,v,o) 投影，仅 q,v 低秩更新的性价比最高。

**一句话总结**：微调的本质改变是低秩的，所以用两个小矩阵就能抓住它——既省又快还不掉点。

***

## 9. 我的理解 / 与后续学习关联

- **本质**：LoRA = 用"低秩约束"这个先验，把"改大模型"的搜索空间从 d² 维压到 2rd 维。
- **与 Attention 的关系**：LoRA 常加在 q\_proj/v\_proj 上 —— 正是 Attention 的 Q/K/V 投影矩阵。下周微调实操可直接验证"改这几个投影矩阵，行为就变了"。
- **与训练循环的关系**：本周 MLP 的 5 步循环（前向→损失→反向→更新）完全适用，只是"要更新的参数"从全部权重变成了 A、B。
